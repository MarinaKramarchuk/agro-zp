# Агро-ЗП — облік шляхових листів і розрахунок зарплати

Веб-додаток для обліковця агропідприємства (Запорізька обл., звідси "agro-zp").
Самостійний (self-hosted, без хмари) інструмент, що замінює паперові шляхові
листи й ручний рахунок ЗП. Опис призначення й функціоналу — `tz.md`.

**Detailed backend reference (модель даних, розрахунок сум, повний API) —
`backend/README.md`. Читай його, а не переказ тут, коли працюєш з бекендом.**

## Стек і структура

- `backend/` — Node.js (Express 5) + `better-sqlite3` (SQLite), валідація `zod`,
  тести — вбудований `node --test` (`tests/unit`, `tests/integration`), без
  Jest/Mocha. SQL написаний просто, з розрахунком на майбутній перехід на
  PostgreSQL (див. "Наступні кроки" в backend/README.md).
- `frontend/` — React + Vite + Tailwind, `react-router-dom`. Сторінки в
  `frontend/src/pages/`, спільні компоненти — `frontend/src/components/`.
- `backend/scripts/seed-demo-data.js` — наповнює чисту БД вигаданими демо-даними
  (`npm run seed:demo`), зручно для першого запуску чи демонстрації.
- `шаблони/` — офіційні Excel-бланки (форма №68, типова форма №2), з яких
  `backend/src/services/waybillTemplateService.js` бере оформлення для
  друку "Друк бланків" (живий runtime-шлях) — не перейменовувати/переміщати
  файли без оновлення сервісу.
- `runtime/` — портативний Node + Chrome-профіль, генеруються локально
  (`.gitignore`), не чіпати як частину коду.
- Корінь: `Відкрити облік.bat` / `Зупинити облік.bat` — запуск/зупинка для
  кінцевого користувача (обліковця), без консолі розробника. Піднімає бекенд,
  який сам роздає зібраний `frontend/dist`, і відкриває
  http://localhost:4000.

## Що робить додаток (розділи меню, `frontend/src/components/Layout.jsx`)

| Розділ | Призначення |
|---|---|
| Огляд | дашборд-зведення (стата, посилання) |
| Дані з техніки | факти мотогодин/пального з телеметрії OVERSEER |
| Плани робіт | план на день (хто/що/де), окремо від фактично внесених шляхових |
| Реєстрація роботи | форма внесення шляхового листа |
| Журнал робіт | список/фільтр усіх шляхових листів |
| Друк бланків | друк шляхового листа й розрахункового листа (payslip) |
| Табель | сітка працівники × дні, кольори за годинами |
| Ремонт (години) | облік годин ремонту техніки (окремо від виробітку) |
| Відомість ЗП | зведений розрахунок зарплати за період, експорт у Excel |
| Контроль гектарів | факт (сума area_ha з шляхових) проти площі поля, по кожному виду робіт окремо |
| Довідники | Працівники, Техніка, Поля, Види робіт, Тарифи, Міжміські рейси |

Дзвіночок сповіщень (`/alerts`) — немаплені записи з OVERSEER/Hecterra,
перевищення площі поля тощо.

## Бізнес-логіка (коротко — повністю в backend/README.md)

- Шляховий лист (`worklogs`) рахується за `pay_mode`: `'tariff'` (з довідника
  тарифів або міжміського рейсу, або вручну введена розцінка), `'hourly'`
  (погодинно від окладу працівника). Розцінка й сума **знімком** зберігаються
  в записі — зміна тарифу заднім числом не перераховує минулі дні.
  Одна ставка мінімалки для погодинних розрахунків — в `settings`
  (`minimum_wage`, редагується в UI, `settingsService.js`).
- Табель рахує години/суми по днях, кольорить комірки (`empty` / `normal` /
  `overtime` / `no_hours`).
- Контроль гектарів порівнює факт із площею поля **в межах одного виду
  робіт** — сума всіх операцій на полі завжди перевищить площу (оранка +
  сівба + ... кожна вкриває все поле), тож загальна сума нічого не каже.

## Інтеграції з зовнішніми системами

- **OVERSEER** (`backend/src/routes/overseer.js`, `services/overseer/`) —
  імпорт Excel-вигрузки телематики техніки (мотогодини, пальне) через
  upload; мапінг машин у `backend/config/overseer-mapping.json`; немаплені
  машини/водії потрапляють у сповіщення.
- **Hecterra** (`routes/hecterra.js`, `services/hecterra/`) — імпорт
  виконаних агрооперацій (культивацій) з експорту Hecterra; немапленi
  поля/види робіт/водії — теж у сповіщеннях.
- **BAS FOR AGRO** (`services/basExportService.js`) — вивантаження шляхових
  у формат для завантаження в бухгалтерську систему BAS. Формат **орієнтовний**
  — реального шаблону завантаження ще нема (портовано з іншого проєкту
  overseer-bas). Джерело даних — вже підтверджені worklogs, а не сирі факти
  з OVERSEER.
- **Gektera** — задокументований у ТЗ, ще **не реалізований**
  (`POST /integrations/gektera/fields` повертає `501`). Дизайн узгоджено
  заздалегідь (draft-and-confirm), доступу до API поки нема — див. пам'ять
  `project_gektera_integration_roadmap`.

## Тести

`cd backend && npm test` — усі тести піднімають застосунок на тимчасовій
SQLite-БД, реальні дані (`data/agro.db`) не чіпають. **Якщо тест ловить живий
баг (не тільки помилку в тесті) — одразу виправляти в коді, а не лишати
задокументованим у червоному тесті** (див. пам'ять
`feedback_fix_bugs_found_during_testing`; так уже був знайдений і виправлений
баг з Zod `.partial().default()`, що тихо скидав тарифні поля на PATCH).
